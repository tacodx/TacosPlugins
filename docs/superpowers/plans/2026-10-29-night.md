# night: implementation plan

**Spec:** `docs/superpowers/specs/2026-10-29-night-design.md` (section 8 overrides earlier sections).
**Branch:** stacked on `feat/reflect`, so the shared files (`.gitignore`, `package.json`, `README.md`,
`scripts/release.mjs`, `release.test.mjs`) carry reflect's changes and night adds one name to each list.

Rules for every task: tests first where the code is pure; a commit per finished unit; no em dashes; no AI
attribution; nothing personal in the code (paths, project names and the artifact URL live in the owner's
`~/.claude/tacos/night/config.json`); nothing on the real machine changes in a test.

## Bulletproof checks (task 14)

Run with `NIGHT_HOME` and `NIGHT_SHARE` pointing at a test folder, so the owner's real night state is untouched,
and with one worker on a scratch repository first:

1. `systemctl --user kill -s SIGKILL night-<name>.service` for each service: the beat returns within 30 s.
2. Kill a worker's `claude` mid-item: the same session resumes (`--resume` in its argv) and the item finishes.
3. `systemctl --user stop night.target`: the keeper starts it again within two minutes.
4. A stale heartbeat file: the medic restarts that unit.
5. A fake health verdict with a blocker: no new item starts; a fake thrash pauses the largest worker.
6. A transcript limit record: the worker waits until a minute after `resetsAt`.
7. Stop mid-item: the phase is `stopped` before anything is stopped, the item goes back open, leftovers are
   committed on the night branch, and the keeper does nothing afterwards.
